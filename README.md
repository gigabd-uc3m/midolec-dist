# Midolec distribution

This repository is the distribution workspace for Midolec executable builds,
runtime assets, configuration files, and user documentation.

The source-code repository is kept separate. This repository is intended to help
internal collaborators install and test packaged Midolec versions without
working directly with the development tree.

## DO NOT MAKE ANY COMMIT
No one should do any commit, unless GigaBD development team aproves.

It is recommended to download the repo. In order to use it, modify it, test it, etc...
as pleased.

You may also clone it. Eventhough it is recommended to make a copy in another folder.


This is just to avoid any unintentional commit or modification of the repository.


## Current status

Midolec V6 is currently an internal evaluation build. Do not treat this
repository as a public distribution channel until licensing and publication
requirements have been reviewed.

The Spanish analysis backend can be configured to use both FreeLing and 
some own PLN functions.

The Enlgish backend currently uses SpaCy.

Still public binary distribution must be reviewed before making this repository
public or publishing packages for external useStill 

Current validation status:

- Spanish/FreeLing is validated in WSL for the current internal binary.
- English/spaCy is validated in WSL for the current binary.


## Quick start for internal testers

1. Download the current Midolec executable package from the latest internal
   GitHub Release.
2. Enter the packaged Midolec folder.
3. Install the required runtime assets:

```bash
cd midolec-v6
gh auth login
bash runtime/provisioning/install_freeling_libs.sh
bash runtime/provisioning/install_freeling_resources.sh
bash runtime/provisioning/patch_freeling_rpath.sh .
```

4. Optional: install the English spaCy runtime if English execution is needed.

```bash
bash runtime/provisioning/install_spacy_en.sh
```

Note: English execution currently works from the source repository. The current
binary package still needs a rebuild that includes `spacy` and `pyphen` inside
the PyInstaller bundle.

5. Run Midolec with the packaged executable:

```bash
./midolec-v6 input_text.txt
```

For Spanish/FreeLing, Midolec V6 uses RPATH/RUNPATH after running
`patch_freeling_rpath.sh`.

See `docs/GUIA_EJECUCION.md`, `docs/DEPENDENCIAS_RUNTIME.md`, 
`docs/VALIDACION_V6.md` and `docs/TROUBLESHOOTING.md` for details.


## Repository layout

```text
midolec-v6/              Current packaged Midolec V6 executable workspace.
midolec-v6/config/       Language-specific TOML configuration files.
midolec-v6/runtime/      Runtime documentation and provisioning scripts.
docs/                    User and maintainer documentation.
releases/                Notes about release packaging. Large binaries are not tracked here.
```

## What belongs in Git

- Configuration files that users may edit.
- Documentation and guides.
- Provisioning scripts.
- Small metadata files such as checksums or release notes.
- The current internal `midolec-v6/` package, while this private repository is
  being used for collaborator testing.

## What does not belong in Git

- FreeLing native libraries.
- FreeLing linguistic resources.
- spaCy downloaded models.
- Generated JSON outputs.

Heavy runtime assets should be attached to versioned GitHub Releases or
generated by the runtime provisioning scripts. For future public distribution,
the executable package itself should also be published through Releases rather
than evolved directly in `main`.
